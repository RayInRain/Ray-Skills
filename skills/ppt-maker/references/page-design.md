# 从内容到可执行页面设计

## 设计与制作的分工

策划端决定页面要表达什么、采用何种视觉形式、主要焦点、阅读顺序和构图。制作端负责模板对象、实际字体、换行、图形与素材落位，并查看渲染结果。文字稿能完成设计意图，不能证明最终版面已经通过视觉验证。

不要把“简洁、高级、科技感、左文右图”当成完整设计。也不要在未测量模板时给每个对象锁死坐标。先明确内容关系与布局约束，再让制作方按实际画布实现。

## 先定整份演示的视觉规则

在主稿顶部集中记录：画幅、使用场景、品牌／模板来源、字体层级、强调色、正文区域和页脚安全区、图表与图形样式、图片处理原则。每页继承，不反复抄写。原生 PPTX 的字号和尺寸不可直接套用 HTML 的 vw、vh 或 CSS 类名。

先读取 [品牌协作契约](brand-contract.md)。本机未指定其他模板时使用已安装英搏尔原始母版，不因用户没上传模板而自由选色建新主题。用户明确使用其他品牌时遵循其模板或规范。字体、字号和信息密度由实际模板、画幅、投屏或阅读用途决定，不把示例数值当成全局标准。

## 先选择表达形式

先写页面结论，再识别它依赖哪种信息关系。

| 内容关系 | 优先表达 | 避免的误用 |
|---|---|---|
| 一个结论与若干证据 | 结论主区＋证据区 | 多个同等强度的大标题争抢焦点 |
| 两个方案或前后状态 | 对齐的维度表、上下流程或并列结构 | 为突出优势而改变对比口径 |
| 数值比较或趋势 | 真实数据驱动的条形图、折线等合适图表 | 用无数据的上升箭头暗示已证实收益 |
| 组成、层级、接口 | 分层结构图或系统关系图 | 用装饰图片代替真实关系 |
| 步骤、阶段、进度 | 流程或时间线 | 把先后顺序误画成已确定因果 |
| 产品、场景、真实证据 | 用户图片、品牌资源或截图＋必要标注 | 生成图冒充实物、实拍或系统截图 |
| 一句话主张、引言、单一指标 | 排版、数字与留白 | 为填空而加无意义配图 |

关系图先明确节点、分组、箭头方向和标签；数据图先确定数据表、期间、单位、分母、来源与轴。正文、数据标签和技术关系保持可编辑。照片或概念插画确有作用而缺素材时，再按当前工具与授权情况安排生成；只有文字任务则提供素材要求即可。

## 让页面真正承担表达

先区分上屏内容、口头展开、证据注释，不能把完整讲稿直接铺在页面上。完整性靠主稿与讲稿承载，页面保留关键结论及足以理解它的视觉证据。

- **有关系就画出关系**：流程要有阶段与方向，架构要有分层／接口，对比要按同一维度对齐。三列标题加三段话仍是文字列表，不能仅因分栏便称为流程图或完成设计。
- **焦点明确、层级克制**：结论与关键证据形成主次，使用留白和对齐组织信息，避免多块同等大小的卡片争抢注意力。不靠多色、装饰线或大面积阴影制造“高级感”。
- **一页有一个阅读任务**：先让人看到关键关系，再读必要细节。内容溢出先改组织与表述，再考虑分拆；不要缩小所有字体填满正文区，也不要删掉结论成立所需的条件。
- **素材提供信息**：真实产品、场景、界面确能帮助理解时使用；没有作用的通用科技图片可以不要。图片不足时不能用空占位图冒充最终设计。
- **复杂页先比较表达**：为核心或复杂页面快速比较两个组织方案，再按理解路径、信息容量与公司气质选择，不用让用户给每个普通页面选模板。

公司框架内的大气、优雅主要由准确的视觉关系、统一层级、克制配色和留白实现。允许正文区添加必要的原生形状与连接线；保护品牌不是只能往旧文本框塞字。

## 逐页设计说明

完整页面设计使用以下顺序；纯大纲、讲稿或局部文字修改不强加视觉字段。各字段可以合并成清楚的短段落，不必逐项堆空表。

1. **页面标识、目的与核心结论**：该页回答什么问题；结论标题、状态词与关键事实的完整文本。
2. **表达形式与选择理由**：明确使用对比、数据、关系、图片证据等哪种形式，并用一句话说明适合当前内容的原因。
3. **视觉焦点与阅读顺序**：第一眼看什么，随后看什么，最后落到什么结论。明确大小、位置或颜色怎样支持这一顺序。
4. **构图与层级**：内容区域、主要比例、对齐轴、主体与辅助信息的关系、留白及页脚安全区。适当写相对比例；只有已核实模板的尺寸才能作为精确约束。
5. **完整内容与素材**：最终页面文字、图表数据或节点关系、来源标识、素材路径与裁切要求。真实素材待补时明确位置与状态，不假称已准备好。
6. **讲稿与时长**：需要口头讲解时保存完整讲稿，按目标时长分配；实际时长未经试讲时标为估计，不只存要点。
7. **确定项、弹性与溢出处理**：必须保留的语义、数字、顺序、品牌对象；允许调整的换行、间距和尺寸；超容量时的替代布局或分拆方向。
8. **验收点与当前状态**：该页最容易出错的地方，以及内容、设计、素材、视觉验证分别到什么程度。

数据表与素材明细可以通过可靠的相对引用关联，但制作方不应为了恢复实际文案去翻旧对话。规划元信息、来源状态和制作指令不放入面向观众的页面正文，除非其本身属于必要说明。

## 版式选择与整套节奏

优先使用当前品牌中已有成功渲染的版式，并记录模板页／版式标识。版式参考应能看到实际缩略图、适用内容、容量和关键组件；只有文字分类的候选结构不能冒充已验证的版式库。

缺少现成版式时，可从以下通用结构开始试制：结论＋证据、前后对比、流程、层级关系、图表＋解读、产品＋标注、时间线、总结与行动。这些是内容结构，不是某个模板已经存在的编号。标题长短、数据量与素材比例不适配时换结构，而不是硬塞。

用简短页序表检查整套演示：每页结论、表达形式、信息密度、主要视觉。连续页面同构且无叙事理由时调整；高密度分析之后可以用清晰结论收束。不为凑版式数量增加无用页面，也不强制所有品牌深浅背景交替。

重要转折、核心论证或复杂页面，可比较两个候选表达，按理解难度、证据匹配、信息容量和制作可行性选择，并保留一句取舍结论。普通页复用成熟规则，不必都生成多个方案或让用户逐页选。

## 代表页试制与视觉回查

实际制作任务中，新模板、陌生版式或内容密集时，先由制作方试制 2—3 个有代表性的页面：一般正文、最复杂的数据／技术页，必要时加封面。已有验证版式且改动小，可以只验证受影响页，不重复建立试制流程。

试制使用最终文字、真实数据和实际素材。简易线框只验证区域与阅读顺序；HTML／SVG 预览可以辅助判断构图，但不能替代目标 PPTX 对字体、换行和对象可编辑性的验证。不要用短占位文字证明长文案能放下。

先自行修正可见问题，再把实际代表页与对应结论展示给用户，讨论内容是否被正确表达、风格和密度是否适合。默认在此节点取得方向再批量制作；用户已明确授权一轮完成或是成熟版式的小改时，可自行验收后继续。不要仅展示一张未经制作的概念效果图就称为 PPTX 代表页通过。

查看实际画面后区分原因：

- **表达方式不适配**：回到页面设计，更换信息组织方式。
- **内容过密**：先精简不改变含义的表述、分组或换版式；必要时按篇幅约束拆页。不能删除必需内容或无限缩字。
- **局部排版偏差**：制作端自主修正换行、间距、尺寸、对齐或合适的裁切，保持已确认语义。
- **需要改变结论、事实或已确认篇幅**：记录问题，返回对应设计决定；只有需要用户作实质选择时再询问。

每次位置修正依据观察与边界测量，不盲猜坐标。同一简单位置问题最多 3 次“修改＋查看”，遵循制作技能已有的更具体计数约定；仍未解决则记录影响并保留最可读版本。换工具、换格式或进入最终检查不重置同一问题次数。结构性调整不能被用来伪装重启同一微调循环；关键内容未能正常展示的页面仍不通过。

只有文字交付时，记录代表页建议与检验要求即可，不自动调用图片或渲染工具；交接状态为设计意图就绪、视觉待验证。试制通过后还需对生成的全稿逐页检查。

## 与英搏尔制作 skill 结合

这是本机默认制作路径，按 [品牌协作契约](brand-contract.md) 加载 `enpower-ppt-skill` 的实际规则与母版。明确使用其他品牌时才切换；所需依赖不可用时如实标记待映射，不能自行替换为泛化样式。

共享设计原则：先选信息表达、单页焦点、统一对齐、留白、克制装饰、关系图与数据可编辑、实际渲染检查。品牌字体、颜色、页脚、Logo、感谢页及可修改区域由实际英搏尔模板确定。

不要将电子杂志／瑞士风的专属 CSS、网页动效、固定深浅节奏和夸张字号比例混入英搏尔页面。每页记录实际使用的源版式及允许编辑的区域；不可读原始母版时只能给品牌框架内的构图建议，并标记版式映射待确认，不虚构源对象标识或声称母版已核对。

交接给英搏尔制作方时明确：接收既有主稿，不重新策划全文；实际套母版、试制、修正与导出由制作方完成。目标格式以本次用户请求为准，不因参考技能的默认双格式或单格式要求自动增加、减少交付。实质设计改动回写主稿。
