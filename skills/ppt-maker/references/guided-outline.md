# 引导用户，把想法发展为完整大纲

## 先听观点，不只收集参数

主题、受众、时长和页数只描述任务外壳，不等于用户想讲的内容。阅读已有材料后，用简短复述展示理解，把事实、用户判断和自己的建议分开。优先补齐影响主线的内容：

- 听众听完应理解什么、改变什么判断，或做什么行动？
- 用户最想讲的观点、亲身例子、真实困难是什么？
- 哪些内容必须讲清，哪些只是背景？听众有什么误解或反对意见？

从中挑 1—3 个当前最有价值的问题，不机械全问。问题具体到场景，可以给方向选项帮助用户表达，但保留自由讲述空间。不要重复询问已知的时长、品牌和受众。

例如用户说：“给部门同事讲 AI 基础，10 分钟，3—4 页。”第一轮应先了解“更想消除对 AI 的陌生感，还是让大家学会一个日常用法”“部门有没有你想拿来讲的工作例子”，并说明会沿用公司模板。可给暂定方向供选择，不能直接断定讲原理还是提效、杜撰部门痛点，然后输出整套文件。

问题发出后等待与主线相关的答复；等待期间可以读模板、整理已有资料、核验通用事实，不能把未回答的问题按默认答案批量推进。若用户明确授权自行判断，则记录假设后继续。

## 帮用户把零散表达整理成论证

收到回答后，归纳为“目标 → 核心判断 → 支撑 → 对听众的意义”。指出缺少的环节或前后矛盾；可提出 1—2 条主线及各自用途，推荐更契合目标的一条，让用户有具体内容可以回应。

引导不是要求用户自己写完整大纲。承担组织、补充背景、简化术语、举例和拆页的工作；用户负责其立场、真实经历及关键取舍。技术培训可用“问题—机制—例子—边界—操作”，提案可用“现状—问题—证据—方案—取舍—行动”；这些是候选逻辑，不是每次固定套版。

若用户说法可能有误，按 [证据纠偏闭环](content-and-state.md) 核实后再写成结论，不盲从，也不凭印象改写。纠正语气协作、说明依据，避免让用户背负自行查清一切的工作。

## 完整大纲的粒度

先给一句主线和章节之间的推导，再逐页展开。每页至少提供：

| 内容 | 必须具体到什么程度 |
|---|---|
| 页面问题与结论标题 | 该页回答什么；听众应带走的结论，避免只有“背景介绍” |
| 内容展开 | 足以支撑结论的要点、例子和必要细节；区分上屏要点与口头展开 |
| 证据或材料 | 对应来源、用户案例、数据或素材；缺项明确写出，不编造填满 |
| 前后页关系 | 为什么从上一页来到此页、怎样导向下一页 |
| 建议呈现 | 对比、流程、关系图、数据、实物证据或一句话；说明内容为何适合 |
| 时长与待决定事项 | 口头演示给估计时间；只列会改变结果的真实缺口 |

列出总页数，封面、目录、附录和品牌感谢页均计入。按讲述深度规划时长，不机械用“分钟÷固定页数”；简短演示不硬加目录。品牌感谢页默认保留，不能为凑数量静默删除。内容与页数冲突时，具体提出合并、减少论点或调整篇幅的选项，按用户决定执行。

大纲在此阶段应已经能判断“讲得通、讲得全、讲得完”，但不要过早逐对象锁坐标。为每页赋稳定标识，确认后在同一主稿继续展开，避免复制出两个竞争正文版本。

## 共识与推进

提交大纲前自检：是否回应用户真正意图、是否偷换主张、支撑能否得出结论、是否有无来源断言、受众能否理解、时长与总页数是否适合。

展示完整大纲或可访问文件，聚焦请用户判断核心主线、必讲／可删内容、缺失例子。不要只问“是否继续”。用户对当前完整方案说“可以”“就这样”“继续”，可视为该范围确认；确认后自主细化，不逐页索要同类确认。

三个协作节点可以合并或由既有材料满足：

1. **需求理解**：已听到用户想讲的观点，或者用户明确授权你提出假设。
2. **完整大纲**：用户看过主线与逐页内容并给出方向；明确一轮完成时保留为 AI 提案状态。
3. **代表页**：核心内容的呈现方式可看、可讨论；实际制作时优先展示真正目标格式的渲染，纯文字任务展示具体设计规格。

已有确认大纲、成熟模板下的局部改字或用户明确的执行型修改，可直接做对应工作。不要把此流程扩张为对所有请求的强制访谈或反复审批。
