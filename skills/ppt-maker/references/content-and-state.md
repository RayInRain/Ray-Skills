# 内容、证据与任务恢复

## 需求与研究

先从用户已有材料形成简短任务说明：用途、受众、用户的核心主张、篇幅或时长、输入材料、输出形式、必须保留项和协作节点。新任务遵循 [引导与完整大纲](guided-outline.md)，不要把自己推断的立场写成用户意图。已知字段不重复询问；不影响方向的实现选择可自主决定。仅大纲或讲稿任务不扩展成页面制作。

将需核验的信息集中到任务级清单，按主题合并研究。遵循用户的资料范围和当前运行环境要求；离线、不可访问或仅限附件时，说明具体证据缺口并继续可完成的部分。

| 信息 | 核验与处理 |
|---|---|
| 用途、受众、风格、页数 | 作为用户约束，不需要联网证明 |
| 用户内部资料 | 核对出处、期间、单位、统计范围与计算；标记“用户提供” |
| 外部事实、近期变化、不确定术语 | 主动联网查原始或权威来源，记录日期和适用范围；用户要求离线或工具不可用时列明未核验项 |
| 观点 | 区分事实依据、推断、建议；必要时补适用边界和反例 |
| 计算值 | 保留输入来源、公式、分母与取整规则，检查总量和比例 |
| 估算、目标、拟议收益 | 标明假设与口径，不写成已经取得的结果 |

同一来源、期间和口径的信息跨页复用；新增结论、来源冲突或口径变化时再检查。公开检索使用必要的通用问题，不把内部原文、个人信息或敏感数字直接送入搜索服务。

重要主张的证据记录包含：标识、主张或数值、来源文件及页码／单元格或网页链接、日期与口径、证据状态、使用页面。状态可为用户提供、外部来源支持、计算得到、假设估算、争议未决。用户接受页面与证据状态分别记录。

来源冲突时比较时间、范围和定义，必要时保留差异。无法支撑的内容可省略、弱化措辞、明确标假设或列为待补；需要的关键事实仍缺失时，不将该稿标为完整定稿。

## 证据纠偏闭环

出现概念混淆、过强断言、数字口径不明、前后矛盾、把相关当因果、用局部案例推出普遍结论时，主动处理，不等用户要求“帮我查”。

1. 指出具体疑点，按主题合并检索。优先原始文献、官方技术文档、权威统计和原始数据；搜索结果摘要不能替代阅读全文中的关键上下文。
2. 对照“原表述 → 存在的问题 → 建议表达 → 依据与边界”，清楚区分已证实的纠正与尚待验证的判断。例如“RAG 会把公司知识训练进模型”需要查清检索、上下文输入与参数更新的区别后改写，不能直接画成同一条训练流程。
3. 不偷换用户的业务诉求。可自主纠正明确错误、补条件和来源；影响核心立场或方案选择时，把证据与具体选项带回大纲讨论。
4. 回写所有受影响页面的结论、正文、图形箭头、数据标签、讲稿与来源。技术关系不确定时，不能用精致的图把不确定性包装成确定事实。

内部数据无法靠公开网页证明；向用户定位原始资料或明确标记待补。保留“估计”“计划”“可能”等必要性质词，不为标题简短而删掉关键边界。无需对纯观点和模板偏好进行无关检索。

## 完整主稿与文件职责

简单任务可在一份 Markdown 中交付，不为流程创建空文件。多轮、多人交接或文件制作任务使用唯一任务目录，例如 `ppt_projects/日期-短名-短随机串/`；继续同一任务时复用原目录。用户指定目录优先，不覆盖其他任务。

推荐按实际需要使用：

| 文件 | 内容 |
|---|---|
| `brief.md` | 当前任务约束、已作决定和版本变更原因 |
| `deck.md` | 唯一当前内容主稿：逐页全文、讲稿、设计说明、证据引用 |
| `state.md` | 工作环节、主稿版本、待解决项、确认范围、制作与验证状态 |
| `sources.md` | 有核验需求时保存证据；少量来源也可直接放在主稿 |
| `handoff.md` | 有独立制作方时保存文件索引、制作任务和权限边界 |
| `assets/`、`exports/` | 有真实素材或导出文件时创建 |

主稿给每页稳定标识，例如 `SL-001`，另记录当前页序。插页或重排不改变既有页面身份。每页保留最终文案与必要全文，而不是仅保存摘要、讲稿要点或“沿用上轮”。讲稿和设计字段按任务需要增加。

跨环节优先读取任务说明、状态及目标页面；事实修改再读对应证据。恢复任务和打包交接时检查完整主稿与文件引用，不要求每次小改都回读所有历史版本。

## 状态、确认与修订

状态记录保存能支持恢复的信息即可：当前环节、当前主稿版本、阻塞项、已完成检查、用户确认对应的版本与页面范围、预期下一动作。分开记录内容就绪、用户审阅、文件制作、视觉验证；不使用一个“已完成”概括全部状态。

新建任务默认按需求理解、完整大纲、代表页的实质节点协作；节点内的研究、自检与实现连续执行。用户说“继续”时按刚刚展示的方案和对应范围推进；不能用它补认从未展示的主线。用户明确要求一轮完成时记录关键假设与“尚未由用户审阅”，自主完成授权范围内工作。已有确认内容不重复确认。

收到修改：

1. 以用户当前明确指示更新任务说明，说明关键假设的变化。
2. 定位受影响页面与依赖：数字关联标题、图表、讲稿、总结；品牌影响视觉和导出；受众或页数影响结构。
3. 在主稿中局部更新，不改无关页。用户要求逐字保持的部分保留原文。
4. 修订版本，记录简短差异；仅使变动范围的旧确认失效，未变部分保持原确认。修改授权不等于对新稿已完成审阅。
5. 重检受影响事实、布局和导出。提供用户所要求的完整稿或差异，不因内部局部更新而遗漏交付范围。

已交付任务可以开启新修订，不回到一套固定起始问答。

## 恢复失败与能力限制

仅有摘要、无法访问附件或找不到完整主稿时，明确不能恢复已确认逐字全文。先定位可访问的版本；仍缺失时请求必要原稿，或提供清楚标记的重建稿方案。不要将新写内容冒充历史定稿。

不能读写文件的环境，在对话中提供完整稿、状态和引用，不声称已经存档。交接依赖尚不可访问的本地素材时，列出具体缺项；不要用另一台机器无法访问的绝对路径作为唯一依据。
