# 纷享销客 CRM

通过用户指定的浏览器访问 CRM。默认完成当前请求所需的查询；创建、修改、审批、发送和导出按用户实际授权执行，本技能不扩展授权。以下路径和流程曾在一个租户中验证，其他租户或界面更新时以当前页面为准。

## 连接和入口

- 优先复用指定浏览器中已打开的纷享销客页面；按浏览器工具文档建立连接，不硬编码浏览器 ID、tab ID、坐标或登录信息。
- 本机已验证可用 `mcp__cua_repl` 操作登录中的 Chrome。先加载其文档；`browser-skill` 的独立会话如果没有连接，不代表用户 Chrome 没有登录，不要因此反复启动浏览器。
- 客户列表：`https://www.fxiaoke.com/XV/UI/Home#paasapp/list/=/appId_CRM/AccountObj`
- 报价明细：`https://www.fxiaoke.com/XV/UI/Home#paasapp/list/=/appId_CRM/QuoteLinesObj`
- 报价单：`https://www.fxiaoke.com/XV/UI/Home#paasapp/list/=/appId_CRM/QuoteObj`
- 审批消息：`https://www.fxiaoke.com/XV/UI/Home#paasapp/remind/454/=/appId_CRM`
- 查价格优先进入“价格管理 → 报价明细”。客户关联报价单标题常不含车型，逐份打开通常效率低。

## 按日期汇总消息及具体报价

用户要求总结报价审批消息时，默认追溯具体报价，不仅复述“审核通过”通知；若明确只要消息概览，则按其范围处理。

1. 按用户当地日期解释“今天”，记录消息时间、客户、申请类型、关联报价单编号。以**通知日期**筛选，不能用报价单编号中的日期或申请创建日期替代。页面中的“今天”需对应当前实际日期，不固定为历史案例日期。
2. 检查列表排序及日期边界。若页面按时间倒序，首页“今天”之后已出现更早日期，且“上一页”禁用，通常足以覆盖当天通知；若排序不明或当日结果跨页，继续检查下一页。不要把其他消息分类也纳入，除非用户要求。
3. 逐一点击通知中的报价单编号，进入“报价单明细”标签。核对 `报价单明细(N)` 数量，读取**全部 N 项**，同单多条通知可按单号去重并保留通知时间。
4. 逐项打开明细，提取产品、型号、物料编码、客户图号、报价用途、含税和不含税报价、税率、数量、审批状态、执行日期；有原报价和变动原因时一并记录。表格横向列未渲染时直接开明细，避免只读可见列就结束。
5. 汇总以产品为行，另列报价单编号与执行期。显示系统原始金额精度，不把散件、样机、量产价格混用。数量为空时不计算订单总额；单位未明确时标“报价（元）”，不自行补“元/台”或“元/件”。
6. 区分用途年份、通知日期和执行期。例如用途写“2025年样机结算报价”但执行期是2026年，应同时保留，不擅自纠正。审批通过也不等于量产价格。

消息链接通常是 `javascript:;`，用页面点击进入，不能把它当作可分享详情链接。无法获取真实详情 URL 时，提供消息入口和报价单/明细编号供定位。

## 快速查询价格

1. 明确用户指定的客户、车型和部件类别。电机控制器/电控、电源/OBC/DCDC、驱动总成分别核对，不能因车型相同而互相替代。
2. 有物料编码时，选“英搏尔物料代码”查询；有客户零件号时，选“客户产品代码（图号）”；只有车型时，可先用“物料名称”查询。
3. **选择搜索字段后先确认页面显示的字段已改变，再输入关键词并提交。** 只输入编码而字段仍为“物料名称”，会导致假阴性。
4. 打开匹配的报价明细，读取完整名称、规格、编码、客户图号、客户、报价用途、含税/不含税价、税率、审核状态、审批日期和执行日期。必要时打开关联报价单补充适用条件。
5. 如果有多条，比较同一物料、客户、用途和有效期间；记录创建时间较新不等于有效报价较新。未通过、样机报价和量产价分别标明。
6. 得到一条身份与价格口径一致、证据完整的结果后即可回答。若存在相互冲突的车型或编码，明确指出冲突，不强行认定。

## 型号搜不到时

- “物料名称没有结果”只表示该字段没有匹配，不代表没有该产品或价格。
- 用页面顶部全局搜索车型，查看产品、商机和样机申请等分类。产品结果可能主要是工装、PCB 或包装，不能当作成品。
- 优先打开同客户、同部件的样机申请，从项目名称、项目编号、技术要求、备注、技术方案确认提取成品编码和客户图号；这些字段可能不一致，应保留来源并回查报价。
- 以提取的明确编码回到报价明细检索。必要时用规格型号或客户图号交叉确认，不遍历猜测的编号或 URL。
- 样机申请中的单价 0 可能是未填写，不能据此说产品免费。样机记录也不自动证明量产结算价。
- 车型名和产品名不一致时，读取 [references/trace-quote.md](references/trace-quote.md) 的通用追溯案例。历史线索不能替代当前页面核实。

## 页面操作经验

- 全局搜索和列表搜索可能都叫“搜索”。先确认当前快照及作用域，避免填错。只有确认页面顺序后才用 `.first()` / `.last()`。
- 下拉菜单和详情抽屉有动画。每次操作后检查当前状态；菜单未打开或抽屉仍覆盖列表时，不使用之前的坐标。一次点击失败后先检查阻挡原因，再依据新截图点击。
- 表格冻结的编号列与数据列可能是两个表；按同一行顺序对应。横向未显示的数据可能尚未渲染，优先打开明细，不把 DOM 中缺少的列当作空值。
- 报价申请抽屉可能同时保留两套明细表 DOM，编号出现两次；依据当前可见表定位，不能重复计数。某些页面可见业务表对应编号的 `.last()`，但仍需现场确认，不能固定依赖该顺序。
- 从多层明细返回时优先关闭最上层抽屉，再打开下一项。若只读页面层级难以恢复，可重新加载消息入口清除抽屉后继续；存在未保存输入时不要重载。已经在相同 URL 上需要刷新时使用工具的 reload，而非重复 goto。
- 读取结果可用 DOM 快照或行文本；避免反复输出所有列标题。通过工具支持的只读 DOM 读取，不依赖私有页面状态或未公开接口。
- 固定宽度详情在窄窗口中可能被裁切。优先使用界面最大化、滚动或用户窗口；若工具允许且确有必要临时调整视口，结束时恢复。
- 仅在工具规则允许的情况下保留用户需要的页面；不要保留每个中间搜索页。

## 交付

先给价格和明确的用途，例如“样机报价，不含税 X 元/台，含税 Y 元/台（税率 Z）”。附型号、物料编码、客户图号、审批和执行日期、报价明细编号及可用页面链接。不要自行推算并声称页面未显示的价格是正式报价。

如果只能确认相关产品，说明哪些匹配、哪些仍不确定；避免把“未找到”写成“系统里没有”。不要把历史案例当作当前事实，或把不相关客户、员工联系方式写入可复用技能。
