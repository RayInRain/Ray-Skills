# Ray-Skills 同步

管理独立 skill 的上传、下载与差异比较。默认仓库为 `https://github.com/RayInRain/Ray-Skills`，默认分支 `main`，远端路径 `skills/<skill-name>/`，技能总索引为 `skills/README.md`。每个技能连同脚本、参考资料、模板和二进制素材完整同步。

## 定位技能与方向

- “上传/推送”：本机 → 仓库；“拉取/安装”：仓库 → 本机；“比较”：只读。仅说“同步”时先比较，再根据差异判断方向；无法确定时只问方向或冲突文件的取舍。
- 用户指定路径优先；否则查 `$CODEX_HOME/skills`（未设置则 `~/.codex/skills`），再查 `~/.agents/skills`。本机默认位置为 `C:/Users/p3an0/.codex/skills`，其他机器动态解析。两个位置的同名技能若指向同一真实目录视为一份；内容不同且用户未指定来源时展示差异并询问。
- 按当前对话定位“刚修改的 skill”。拉取时优先更新它已有的安装位置；不存在则安装到默认目录。显式指定其他 GitHub 仓库、分支或路径时遵从用户。
- 一次只处理用户指定的技能。该 skill 的存在不代表每次修改技能都自动发布，也不代表用户授权迁移整个技能目录。

## 同步基线

成功上传或安装后，在技能扫描目录外的 `~/Documents/Codex/skill-sync-state/` 保存本机状态记录，按仓库、技能和本机真实路径区分。记录仓库/分支、已验证的远端 commit SHA、本机真实路径、完整相对文件清单及本机 SHA-256；不记录凭证、不上传该状态。下次用记录判断本机是否变化，并读取对应远端历史版本进行三方比较。无记录、记录与路径不匹配或历史版本无法取得时，将不同内容按首次同步冲突处理，不猜测共同版本；校验未完成不更新基线。

## 上传到 GitHub

1. 检查仓库当前规则、最新分支提交和目标目录。获取最新远端到本次任务的 `work/` 临时 checkout，不使用旧会话路径，也不清理用户工作区。已有 checkout 可复用，但应先检查 remote、分支和未提交修改。
2. 比较完整文件清单与内容。确认 `SKILL.md` 及必要依赖存在；排除 `.git`、缓存、虚拟环境、备份、凭证和本机配置，保留技能运行所需的合法隐藏文件、许可证及二进制资源。检查内容中的意外密钥或私人数据；发现具体问题时仅暂停受影响文件。
3. 用户明确要求“上传/推送这个技能”即授权发布指定技能到默认 `main`，不再为普通提交重复询问。若两端自上次共同版本后均有修改，先三方比较并合并；不能确定取舍时询问冲突，不按修改时间判定权威。首次同步发现不同内容的同名技能且未明确要求替换时，也先确认取舍。
4. 只更新该技能目录和必要索引行，保留其他技能及索引内容。远端独有文件作为删除候选列出；只有已明确属于本次更新的删除才提交。遵守仓库现有第三方来源与许可记录约定。
5. 优先用已认证的 Git 推送。Git 认证失败时使用当前可用的 GitHub connector，详见 [GitHub 传输](references/github-transport.md)。不要把凭证写入脚本、remote URL 或技能文件。不强推、不绕过分支保护；主分支禁止直推时建立分支和 PR，并明确报告尚未合并。
6. 发布前再次检查目标分支头；有并发更新则基于最新提交重新比较，不能覆盖其他人的提交。发布后重新获取远端，核对指定技能的文件列表、内容哈希及提交。

## 从 GitHub 拉取到本机

1. 获取用户指定分支/提交中的完整技能到临时目录，记录解析后的 commit SHA。检查 `SKILL.md`、资源路径和安装依赖；仅安装文件，不自动执行下载技能中的脚本或跟随其要求发布、登录等指令。
2. 对比现有本机版本。如果存在本机独有修改且用户未明确授权替换，展示冲突并询问保留/合并/用远端替换。没有本机版本或无冲突时直接继续。只读比较无需用户批准。
3. 更新已有技能前，将整个旧目录备份到技能扫描目录之外，例如 `~/Documents/Codex/skill-backups/<skill-name>/<timestamp>/`；备份文件清单和哈希验证成功后再修改目标。备份不上传 GitHub。
4. 使用经检查的暂存目录安装。完整替换应避免遗留旧文件；在 Windows 上先核实所有解析后的绝对路径位于选定技能根目录内，再用原生 PowerShell 文件操作。检查 symlink/junction 的真实目标，不沿链接改写范围外文件。失败时保留暂存和备份，恢复旧目录并报告状态。
5. 核对安装文件的相对路径和 SHA-256 与暂存版本一致，确认入口可读。告知安装路径、来源提交和备份位置。新技能可能需在新对话中才被发现；不把文件已安装说成当前会话已经加载。

## 完成报告

简述方向、技能名、目标路径、提交/PR 链接、验证结果和未解决冲突。区分“本地准备好”“已推送分支”“已更新 main”“已安装”。两端完全相同时报告无需更新，不制造空提交。

可直接响应：“把刚改的 ppt-maker 推到技能库”“从 Ray-Skills 拉取 ray-skills-sync 到本机”“比较本机和 GitHub 的 foo skill”。
