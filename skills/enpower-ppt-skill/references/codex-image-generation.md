# Codex 图片生成与编辑

本流程适用于制作演示时需要的照片、插画、概念图、产品场景图、透明素材和图片编辑。调用 Codex 内置图片工具，不只是给用户一段提示词。工具名称与参数以当前会话暴露的定义为准，不绑定某个图片模型名称。

## 何时调用

先读取 `visual-planning.md`：根据内容和页面效果选择表达方式，不给 SVG 或原生图形固定优先级。主动规划与主题相符的图片；关系、流程、架构页也可配产品、场景或概念图片，并与图形组合。需要生成或编辑位图素材时进入下面流程。

- 用户明确要求照片、插画、位图背景或重绘现有图片时直接执行。一般性的“生成配图”“自动配图”按主题与页面效果选择图片、图形或组合，不因关系图可以用 SVG 表达就省略有价值的主题图片。
- 用户要求实际 PPT 时，先使用已有品牌素材和用户图片；已授权制作范围内确有表达价值的概念素材可调用内置工具生成，不逐张重复确认，也不默认每页生成。纯文字设计任务只提供素材需求；真实产品缺照片时不擅自用概念图替代。
- 用户已授权整份演示自动配图时，自行判断必要页面、图形方式与数量，不逐张请求确认；不需要图片的页面不生成。
- 标题、正文和需要编辑的数据图表保留 HTML/PPTX 可编辑对象；流程和关系根据用途选用图形或图片，合适时组合使用。生成图作为独立位图素材，不用整页图片替代可编辑幻灯片。
- 公司 Logo、二维码、真实园区照片和真实产品图片使用已有素材，不用生成图冒充实物或重画品牌标识。没有真实素材时，生成内容标注为概念示意。

## 调用步骤

1. 在逐页计划中确定主题、主体、受众、媒介风格、素材用途、比例、落位和需保留的信息。让风格契合内容，示例中的电驱系统等主题不作为通用默认。默认 C 风格使用 `image-prompts.md` 的英搏尔提示词，A/B 才使用各自提示词。
2. 如当前环境提供 `imagegen` skill，读取其说明。发现并调用内置 `image_gen` 工具；当前工具可能显示为 `image_gen.imagegen`，在 `functions.exec` 中对应 `tools.image_gen__imagegen`。不得只宣称已调用。
3. 新图只传入提示词及透明背景选项。比例、构图和文字要求写在 `prompt` 中，不虚构 `model`、`size`、输出路径等当前工具未提供的参数。
4. 编辑本地图片前用 `view_image` 查看原图，再通过 `referenced_image_paths` 传入实际绝对路径。若目标仅存在于会话附件中，使用覆盖所有目标图片的最小 `num_last_images_to_include`；这两个参数不能同时使用。不要猜测附件路径。
5. 保留透明背景时设置 `transparent_background: true`，普通不透明新图设置为 `false`。编辑时保持原图透明性，除非用户要求改变。
6. 等待生成完成，遵守工具当前的等待约定。用 `generatedImage(result)` 展示结果，不输出原始 base64。不要在工具返回前声称生成成功。
7. 从工具结果中获取实际产物位置。内置工具通常保存到 `$CODEX_HOME/generated_images/` 下，但不能猜文件名或简单选“最新图片”。若返回内容未给路径，按返回元数据定位并核对图像；只有远程结果时使用工具支持的保存方式。拿不到文件时说明集成受阻，不填写虚假路径。
8. 将选定图片复制到演示目录的 `images/`，使用 `{页号}-{语义}.png` 等名称。保留真实格式和透明通道；不要把 JPG 改后缀当作 PNG。已有同名素材未要求替换时使用 `-v2` 等版本名。
9. 查看生成图，核对主体、文字、参考图需保留的内容和比例；必要时针对具体问题编辑一次再复核。提示词要求的比例不等于已验证的实际尺寸。
10. 完成下述 HTML/PPTX 集成与视觉检查，再交付文件。

## 内置工具调用示例

此示例用于需要生成新图时，替换主题与比例后调用；不是安装脚本。若工具名称不同，按当前会话定义调整。

```javascript
// @exec: {"yield_time_ms": 120000, "max_output_tokens": 1000}
const result = await tools.image_gen__imagegen({
  prompt: "为英搏尔品牌技术汇报生成新能源汽车电驱系统概念配图。白色与浅灰背景，品牌蓝 #005687 为主，少量品牌红 #E10600 强调，专业克制。16:9 横向构图，主体完整且四周留白。仅生成概念画面，不含文字、Logo、二维码、水印或幻灯片外框，不冒充真实产品照片。",
  transparent_background: false
});
generatedImage(result);
```

编辑时沿用同一工具，提示词明确“改什么、保留什么”，并增加以下参数之一：

```javascript
// 所有目标图片都有本地路径时（先查看图片）
referenced_image_paths: ["C:/实际演示目录/images/03-product.png"]
// 或目标只存在于近期会话图片中时
num_last_images_to_include: 1
```

## 插入与交付

- **HTML**：开发时用 `images/文件名` 相对路径插入实际存在的文件；单文件交付前转为内嵌 data URI。C 风格只使用品牌模板已有类或明确的局部样式，不套用 A/B 的图片类。照片可适当裁切，带文字或技术细节的图片使用完整显示，防止关键内容被裁掉。
- **PPTX**：按 Presentations skill 的工作流将同一素材嵌入为独立图片对象。正文、标题、标签和图表保留为可编辑对象；图片内部像素内容不宣称可编辑。保持母版、Logo、页脚和品牌感谢页。
- **双格式**：内容和素材含义一致，按各自版式适配大小。只请求一种格式时，仅集成到该格式。
- **位置调整**：遵守 `visual-planning.md`：同一简单位置问题最多 3 次修改与检查，未解决则记录并继续，交付时统一报告。不得为位置问题反复重新生成图片。
- **验证**：检查图片文件存在、可打开、路径可移植；仅对本次目标格式打开 HTML 或渲染 PPTX 的相关页面，核对裁切、遮挡、文字可读性及品牌一致性。仅 HTML 时按 `delivery-format.md` 内嵌图片和全部运行资源，交付单文件；双格式的多文件 HTML 才附带所需图片目录。
- 在项目记录中记下最终提示词、实际使用的生成方式和图片文件名。交付说明简述生成素材及仍需用户确认的概念示意，不能把未执行的生成或未检查的页面说成已完成。

## 工具不可用时

内置工具不需要用户配置 API key。若工具缺失或失败，如实说明，可继续整理已有素材和版式，不伪造成功结果。只有用户明确选择 API/CLI 回退后，才按当前 `imagegen` skill 的回退流程配置；不自行安装依赖、要求聊天中粘贴密钥或静默切换到付费 API。

## 协同制作衔接

实际制作时结合 `integrated-production.md`：在原逐页主稿规划图片作用与图形/文字分层，维护 `images/assets.json` 并核对实际文件，检查页面及全稿节奏。沿用本文件的主题表达和三次位置调整上限，不增加重复确认。
