# 图片、图形与原生模板的协同制作

这是英搏尔制作流程的补充，不是另一个必须完整执行的工作流。借鉴 PPT Master 的素材分工、可编辑导出和保留原稿编辑思想，以用户要求、公司模板与共创契约为准。

## 保留的要求

- 默认英搏尔 C 风格、原母版固定品牌层和感谢页；按 `delivery-format.md` 确认仅 PPT、仅单文件 HTML 或两者都要。
- 图片、SVG、原生形状不设固定优先级。按主题选择，主动安排对应图片，可与关系/流程/架构图组合；高端、优雅、清晰，不堆砌。
- 用户明确的主体、位置、顺序、数量、文案和已确认大纲必须落实。继承已确认方案，不重复策划或增加上游的多轮确认门槛。
- 同一简单位置问题累计最多 3 次“修改 + 检查”；换工具或最终检查不重置。未解决则记录、继续其他页、最后统一报告。完整性或数据错误如实标为未通过，不通过无限位置微调掩盖问题。
- 内置图片工具是 Codex 生成/编辑图片的默认方式，不静默切换付费 API。动画、旁白、视频等不因工具支持就自动增加。

## 1. 每页先确定任务与组合

直接在已有逐页主稿中补充以下内容，不另建竞争版本：本页结论、来源、明确布局约束、主视觉作用、图形关系、可编辑对象、所用素材、验收点。已存在的信息直接复用。

将内容与表达方式分开判断：表达关系可以用节点连线，也可以是产品照片加标注、场景图加流程、剖面图加分区说明。先确定阅读顺序与信息关系，再选择合适形式；不强制所有信息放进卡片，也不把每页做成文字加矩形框。

图片作用可选：局部说明、案例证据、主体特写、内容区主视觉、章节氛围。品牌固定层始终保留；“主视觉”不意味着生成整页图片替换公司封面或感谢页。标题、正文、精确数据和需要修改的标签作为独立对象。图片内部文字只用于不需要编辑的少量画面内容，并核对准确性。

同页可组合独立图片、SVG/原生图形和文字；标注贴合主体，连接线方向明确，图层不遮挡品牌或关键信息。投影、裁切、透明度等按实际工具能力使用，不把可在版面实现的简单位置变化反复交给图片模型重画。

## 2. 先定图片方向，再准备素材

在主稿中简记整份演示的视觉基调、品牌色角色、主要图片媒介和统一尺度。逐图说明主体、作用、构图、比例和文字/标注预留区；只在实际有叠加文字的区域要求留空，不把每张图片都做成空白背景。不同主题允许采用相符的媒介，不强迫照片、技术示意和插画画成同一种形式，但要保持整体协调。

维护一份 `images/assets.json`，每项记录：

```json
{
  "id": "asset-03",
  "file": "images/03-drive-concept.png",
  "pages": [3],
  "role": "内容区主视觉",
  "source_type": "generated",
  "source": "内置图片工具；提示词记录位置",
  "status": "planned",
  "target_ratio": "16:9",
  "actual_size": null,
  "crop_policy": "保留完整主体",
  "editable_labels": ["输入", "输出"],
  "credit": null
}
```

`source_type` 为 user / brand / generated / web / derived；`status` 为 planned / ready / unresolved。复制、生成或获取完成后，检查真实文件、尺寸和内容才改为 ready。派生素材另记 parent_id，保留原图。网络图片记录原始页面、作者、许可和所需署名，不因能下载就视为可使用。此流程不要求联网搜图；已有素材和内置生成能力可独立完成。

需要图片时读取 `codex-image-generation.md`。记录最终提示词；图像落入项目目录后再引用。网页开发时使用相对路径，仅 HTML 交付时内嵌所有运行资源，PPTX 嵌入媒体，不依赖默认生成目录。交付前逐项核对实际页面与清单：禁止将 planned 当成已插入，unresolved 项说明影响和替代方案，不偷偷换成不相关图片。

## 3. 原生模板编辑与可选 PPT Master 工具

默认使用 `pptx-output.md` 的 Presentations 制作方式。若已安装的 PPT Master 提供适用的保留原稿工具，可选择其 Edit Native PPTX 路线；这是可选依赖，不要求安装、升级或复制整个工具仓库。

使用前从当前技能目录中确定 PPT Master 的实际绝对路径，读取其入口和对应原稿编辑文档，检查安装版本和命令帮助。不能假设网上 6.9.0 的功能已存在于本机旧版本。不要同时运行 Generate 的新建流程和 Edit Native 的原稿保留流程；不要将现有 PPT 仅当作素材后从空白仿制母版。

工具选择前在工作目录用源母版副本做一次无内容修改的往返验证：检查导出后封面、正文、图表、感谢页，及 slideMaster/slideLayout/theme、品牌对象、字体、图表数据和媒体。再用一页真实内容验证选定对象修改。不能只凭命令成功或 SVG 预览相似认定母版保真。

验证通过后保留源文件及哈希，登记源页到输出页映射；未修改页面与对象沿用原生内容，只修改所需业务对象。若采用安装版本支持的 roundtrip 工具，遵循其原生备份与引用契约，不手改工具维护的 backing 数据。不支持的品牌对象不可凭外观重画替代。

选择该方式时，允许使用 PPT Master 自身的原生转换/编辑依赖；原先 `@oai/artifact-tool` 限定只适用于默认制作方式。仍禁止临时另写一套 python-pptx 空白重建母版的捷径。选择记录包含工具、版本、验证结果与限制；默认方式失败不等于其他方式自动通过。

SVG 可以作为局部设计源或转换中间件：转换后检查目标确实是原生文字/形状/连接线，而非单个 SVG 图片。只有需要“编辑数据”的图表才承诺原生 Chart + 数据工作簿；可编辑图形组成的柱状图不等同原生数据图表。复杂效果可能栅格化，必须说明实际编辑范围。

若工具不能保留必需模板对象，停止使用该工具制作正式成品，保留内容方案和失败证据。可以继续不受影响的页面/HTML，但 PPTX 标记未验证或草稿，不假称已保真。技能本身的模板资产不被修改。

## 4. 验证与交付

先用真实文案和素材完成代表页，按已有确认范围继续。全稿检查两种尺度：逐页看裁切、对齐、字号、关系、图片和品牌；缩略图总览看版式节奏、重复、密度与整体协调。避免只有“没有重叠”就认定设计合格。

最终重新打开导出文件，分别记录品牌保真、内容准确、视觉质量、实际可编辑性和素材完整性。将一轮发现的问题合并处理，再检查受影响页面；简单位置调整遵守三次上限，不因批量处理重新计数。

复用项目记录保存待办表：页码/格式、元素、问题、已尝试次数与方案、当前影响、后续建议。交付时一次性报告未解决和未验证项。没有问题不制造空报告；不把失败页说成全部通过。
