# 公司模板、用户共创与制作契约

适用于默认 C · 英搏尔品牌任务，以及 `ppt-maker` 向本 skill 的交接。公司模板固定；设计工作在模板允许的正文区域内完成。用户明确选择另一模板或 A/B 风格时按该选择执行，不能把“优雅、极简、信息图、技术感”解释为换模板。

用户明确要求改变某个品牌项或删除感谢页时，记录具体覆盖范围，并据此验收；其余固定项继续保持原样。不能由一般的美观或篇幅要求自行扩大覆盖范围。

## 共创节点与已有确认

默认从用户的想法开始，一次集中问 1—3 个影响结果的问题，带着材料和理解引导用户讲明白。不能只收集受众、时长、页数，就自行猜测核心观点并批量出稿。

| 节点 | 给用户看的具体内容 | 下一步条件 |
|---|---|---|
| 需求理解 | 目标、受众关注点、用户核心判断、理由/案例、希望推动的行动；区分已知与待补 | 用户补充或认可，或已有同范围确认 |
| 完整大纲 | 章节逻辑与逐页问题、结论、展开要点、依据、前后衔接、建议视觉形式、待补项 | 用户能评价内容而不只评价标题；落实反馈后展开 |
| 代表页效果 | 实际模板上的一般正文、最复杂页面；新封面处理有风险时包含封面；说明设计取舍 | 展示实际效果，落实用户反馈后批量制作 |

节点可合并，不机械按编号等待。用户明确要求不提问、直接完成或已经授权自主决定的范围，可按已知信息继续并说明重要假设；这不改变模板和质量要求。单纯提供主题或说“做一份”不等于放弃参与。用户回答前可读资料、整理证据和搭建待讨论草稿，不把沉默当成确认。

接收上游 `ppt-maker` 交接时，先读主稿版本、用户确认范围、来源和未决项。已经确认的意图与大纲直接复用，进入下一未完成节点。仅对新增冲突或会改变结论、范围的缺口询问；不要求用户重复所有答案。普通局部改字不重启共创，新受众、新观点或重大结构变化才回到受影响节点。

## 从想法到完整大纲

- 追问“你为什么这么判断、有什么实例或数据、听众会反问什么”，帮助用户补论据和边界；保留用户的真实主张，不为流畅虚构事实。
- 每页至少说明：本页要解决的问题、一句主结论、能讲开的要点、支撑材料/证据、与前后页的逻辑、拟用的视觉表达。完整大纲不是目录，也不是一串标题。
- 有术语疑义、数字矛盾、因果跳跃、比较口径不一或外部事实不确定时，先核验原材料与计算；对外部问题联网查原始或权威来源，提供“问题—依据—建议改写”。无法核实则保留不确定性质；内部数据核对出处，不用公开搜索冒充内部核实。
- 从“背景/问题—证据—判断—方案—行动”等适合场景的逻辑组织，不把所有任务都变成固定故事弧。推断、计划和已实现成果应明确分开。
- 已确认全文保留在一份主稿中，页面使用稳定标识。实质修订同步数字、图表、结论和讲稿；制作指令、核验记录不混入受众正文。

## 母版固定层与正文设计区

| 层 | 允许操作 |
|---|---|
| 原始资产 | 使用 `assets/empower/reference.pptx` 及原始品牌媒体；记录来源及 SHA256，不修改 skill 的源文件 |
| 固定品牌层 | 保留源 slideMaster、slideLayout、theme 的视觉定义及品牌对象：背景、Logo、蓝红品牌色、字体、页眉页脚、版权线、园区和二维码；不移动、重画、替换或重配色 |
| 业务内容层 | 替换封面标题/副标题等已确认业务占位；在测量登记的正文区域内设计结论、证据、对比、流程、层级、数据图表、产品标注和图片。使用原生可编辑文本、图形、连接线和图表 |
| 品牌感谢页 | 继承源第 4 页及其布局，保留 THANKS、两行品牌口号、二维码和园区，不擅自添加日期、汇报人或额外口号 |

PPTX 先检查源页以及它继承的布局、母版、主题、字体和媒体，不能只查看 slideN.xml 的直属对象。源页 1/2/3/6 分别用于封面/目录/通用正文/图表，源页 4 用于感谢页；源页 5 为使用须知，7/8 为 ICON 库。具体对象 ID 和正文坐标必须从当前母版读出，不能根据编号猜测。

`template-frame-map.json` 至少记录：来源文件及哈希、源页与布局/母版关系、固定对象、可编辑业务占位、正文区域边界及单位、计划新增的正文对象。源占位位于继承布局时，在当前业务页填入对应内容，不改共享母版定义影响其他页。固定对象即使位于正文附近也要保留，不能按包围盒一刀切删除。

允许为内容组织新增原生关系图表，不要求照抄源页示例的业务布局。明确焦点、阅读顺序和留白后再放内容；不把同一文本框装满段落，也不把每页都变成三张等宽卡片。放不下时精简不改变意义的文字、调整分组/版式或按约定拆页，不能缩字到模板要求以下。

默认 C 禁止从空白画布重新绘制“相似模板”，禁止用整页截图冒充可编辑 PPTX。`scripts/build-empower-cover-pptx.mjs` 不是母版保真制作路线；不因它能生成文件就用于替代模板继承。工具无法保留母版时记录具体限制，继续完善内容交接，不宣称成品通过。

## 交接必须带什么

复用上游唯一主稿，不复制一个可独立修改的第二正文。交接带上目标格式、用户确认范围、模板来源、固定项/可编辑区、页面顺序与全文、逐页设计、真实图表数据、素材路径及待补状态、代表页和验收点。已有内容不重策划；制作端可自主修正换行、间距和裁切，改变核心表达则回写主稿及受影响确认。

按 `delivery-format.md` 提供仅 PPT、仅 HTML、两者都要三种选择；未指定时询问一次，已明确则沿用。仅 HTML 必须内嵌资源交付单文件。仅文字或交接包遵循该范围。HTML 使用现成品牌网页模板，PPTX 继承原始 PPTX，各自验证，不将网页截图作为 PowerPoint 内容。

## 两项验收分别成立

**母版继承与品牌保真**：

1. 制作前查看原母版的封面、正文、目录、图表和感谢页参考，记录固定品牌对象及继承关系。模板文件存在或哈希匹配只证明来源，不证明输出保真。
2. 对最终导出的 PPTX 重新打开并渲染，核对实际继承关系、固定对象位置/比例/颜色/字体、Logo、页脚、背景、二维码、园区和感谢页，与源参考并排或叠加对照。
3. 能检查文件结构时比较 master/layout/theme 及媒体，区分编号重排等无视觉影响变化与真实丢失/重绘。仅导入导出成功、内部预览相似或脚本退出成功都不能判为通过。
4. PPTX 与 HTML 分别记录检查结论。无法查看目标格式或有品牌偏差时标记未验证/未通过，不用“使用了品牌蓝”代替母版检查。

**内容与视觉质量**：

- 逐页判断结论是否有依据、视觉形式是否表达信息关系、单页焦点和阅读顺序是否清楚；适合对比、流程或图表的内容不退化成段落堆叠，单一主张或数字可用排版与留白表达，不强制每页配图。
- 用最终文案、数据和实际素材试制并展示代表页；使用短占位词或空白框不能证明完成设计。照片/插画只承担有价值的视觉作用，精确数据和关系不交给图片模型猜测。
- 全稿逐页检查并查看缩略图总览：对齐、层级、留白、密度、图形尺度和节奏协调；没有重叠只是基本条件，不是美观通过标准。
- 需要编辑的对象检查实际可编辑性。修正和未解决问题按 `visual-planning.md` 记录；不能将达到微调次数上限的失败页标成通过。内容准确、用户认可、品牌保真、视觉质量和文件可编辑是不同状态。

交付只报告实际完成和检查过的部分；模板保真或关键页面阅读仍失败时交付应标为草稿/部分完成，给出具体缺项和后续动作。
