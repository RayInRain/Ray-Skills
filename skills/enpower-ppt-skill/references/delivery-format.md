# 交付格式选择与单文件 HTML

## 先明确交付选项

实际制作前检查用户本次要求和已有确认。格式明确就直接执行，不重复问；未明确时一次询问：“这次交付哪种格式：① 仅 PPT（可编辑 .pptx）；② 仅 HTML（单文件）；③ PPT + HTML？”可与其他必要问题合并。

- `pptx`：仅制作可编辑 PowerPoint，默认扩展名 .pptx，不另外生成 HTML。
- `html`：仅制作一个可独立打开的 .html 文件，不另交 PPTX 或必需的素材文件夹。
- `both`：制作 PPTX 和 HTML，内容一致、各自验证。HTML 可按原流程携带素材目录；用户要求单文件时执行下述单文件要求。

“做个 PPT”可能只是泛指演示，不能据此假定双格式；明确说“只要 PPT / .pptx 文件 / PowerPoint 文件”时直接选 pptx。“只要 HTML”直接选 html。已确认的格式在同一任务后续修改中沿用，用户新要求可覆盖。

格式等待期间可整理内容、核对素材，不把沉默当成选择，不默认启动两套制作。仅当用户明确要求“不提问、自主决定”且无格式信息时，沿用 both 并说明采用的格式。仅大纲或文字任务不触发此选择。

在已有项目记录记下 delivery_format 和 html_packaging（single-file / folder），不额外制造独立配置文件。

## 仅 HTML：最终必须单文件

开发阶段可使用模板、images/、empower/ 和脚本文件夹，最终交付时将运行所需资源嵌入一个 HTML。单文件是交付形态，不是把所有页面变成截图；保持文字可选中、SVG/HTML 图形、翻页交互和品牌视觉。

1. 样式放入 `<style>`，运行代码放入 `<script>`。本地及 CDN 脚本依赖需打包内嵌；模块 import、动态 import、fetch 和 worker 不能残留外部运行依赖。保留必要第三方许可证说明。
2. 图片使用正确 MIME 的 data URI，含 Logo、二维码、背景、正文配图、SVG image href、srcset、poster 与 CSS url()。SVG 可直接内联；SVG 内引用的图片也须内嵌。实际格式不靠改扩展名转换。
3. 字体使用可用的系统字体栈，或在许可允许时嵌入字体。禁止依赖在线字体才能正常显示；系统字体跨电脑可能略有差异，实际复核中文换行。
4. 若演示需要音视频等媒体，将其内嵌；过大的素材可在保留阅读质量的前提下压缩，不通过外链规避单文件要求。
5. A/B 风格的图标可预先内联 SVG，动画库可内嵌或用等效本地逻辑。地图等联网组件无法完整离线时，改成保留信息的静态内嵌示意并说明交互差异；不能把联网网页标成离线单文件。
6. 使用普通 file:// 打开即可演示，不需要本地服务器、联网、缓存、同目录资源或浏览器特殊权限。引用出处的可点击超链接可以保留，但不能是必需运行资源。

## 单文件验收

- 将最终 HTML 复制到一个不含素材的独立检查目录，用新的浏览器上下文打开并阻断网络，避免已有缓存掩盖问题。
- 逐页检查图片、背景、Logo、二维码、字体可读性和布局；测试前后翻页、导航点击，以及实际提供的快捷键。
- 检查控制台和请求失败；扫描资源属性、CSS url()/@import 和脚本加载，确认没有必需的本地路径或远程依赖。data:、内联内容和内部锚点可用，运行时 blob: 仅在内容由文件内部生成时可用。
- 结构检查不能替代离线视觉检查。未验证或仍有外部运行依赖时，记录具体项，不宣称单文件离线通过。
- 最终给用户一个 .html 链接，不要求用户保留 images/、empower/、JS/CSS 文件或下载 ZIP 才能播放。开发资源留在工作目录，需要时可另行提供，但不是运行前提。

所有格式继续遵守英搏尔默认风格、主题配图、可编辑性说明及同一位置最多 3 次调整的要求。
