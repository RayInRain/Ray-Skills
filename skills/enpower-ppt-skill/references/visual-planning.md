# 视觉选择、布局与有限迭代

制作所有风格、所有输出格式前，先按本页选择视觉表达。默认保持英搏尔品牌模板；配图风格在品牌框架内服从内容主题，不把每一页都做成同一种科技概念图。

## 明确布局的执行与验收

用户提示词中的明确排版要求，以及用户已确认并要求据此制作的大纲、页面方案，都是布局约束。“建议画面”一旦被采纳，不能仅因标题含“建议”就忽略。未经用户采纳的候选方案仍是提案，不自动成为约束；用户后续修改覆盖对应旧要求。

### 制作前：把要求变成逐页可检查项

在唯一主稿或项目记录中，为有明确要求的页面记录：

| 字段 | 记录内容 |
|---|---|
| 要求来源 | 对应用户原话或已确认方案，不将自己的猜测写成用户要求 |
| 必需元素 | 指定主体、图片、文字、图形、数量及指定上屏文案 |
| 空间关系 | 中心与四周、左右、上下、环绕、对比、流程顺序等；明确比例与位置也需记录 |
| 可自主决定 | 未指定的具体坐标、尺寸、间距和实现方式，须保持上述关系 |
| 验收依据 | 实际导出页／HTML 截图及每项符合、未符合或未验证的状态 |

先满足这些约束，再在允许区域内优化美观。不得以模板默认、排版方便、赶时间或“内容一样”为理由，将指定的环绕图改成几列文字、将图片主体删掉、交换指定左右位置或将指定上屏文案只放进备注。明确给出的标签、引导提问等上屏文案默认保留原文；用户授权改写时按授权执行。

已有模板时，优先在正文区域内实现要求，保留未被用户要求改变的品牌元素。常规字号、留白、断行和坐标调整可自主完成，不逐项确认。确有无法同时满足的要求时，先完成可行部分并明确冲突；只有必须改变指定布局、内容或品牌约束时，才请用户决定具体取舍。未完成的要求必须如实标注，不得静默换版式后声称完成。

### 导出后：内容与布局分别验收

逐页查看最终输出，并对照记录检查：必需主体是否可见、相对位置是否正确、数量和顺序是否完整、指定文字是否在画面上原文呈现。以实际画面为准，代码里声明了坐标或图片路径不能证明布局已落实。双格式分别检查，不能用 HTML 的正确截图证明 PPTX 正确。内容齐全、无溢出、品牌保真与布局符合是不同的验收项。

例如，要求“以一杯红茶为中心，围绕‘看、闻、尝、回味’，配‘闻到了什么？入口怎样？咽下后留下什么？’”，则画面必须具有中心茶杯、环绕的四个动作和三个原文提问。四列文字即使涵盖全部知识点，仍不符合要求。未指定四个动作的具体方位时，可自行安排；该示例不要求其他页面也采用环绕布局。

## 先判断是否需要视觉素材

先明确页面要传达的结论，再选择表达方式，不设置 SVG、原生图形或图片的固定优先级。主动寻找与主题对应的产品、应用场景、案例照片、插画或概念图片，让页面丰富、有层次，避免全稿都是文字、方框与连线。关系图可与相关图片同页搭配，例如产品照片配架构标注、应用场景配流程。“自动配图”表示自主规划合适素材与组合方式，不要求每页调用图片模型；少量结论页可用简洁排版形成节奏，图片仍需与内容相关。

| 内容需要 | 可选方式 | 使用要求 |
|---|---|---|
| 关系、架构、流程、组织、时间线 | HTML/CSS、SVG、PPTX 原生图形、主题图片或组合表达；合适时用 Mermaid 排图 | 按信息结构与视觉效果选择，节点与方向保持准确；可搭配产品、场景、案例或概念图丰富页面 |
| 精确数据、比较、趋势 | 原生图表或基于真实数据生成的矢量图 | 数值和标签必须来自提供或核实的数据，不由图片模型猜测 |
| 照片、真实产品、园区、截图 | 用户素材或已有品牌资源 | 真实对象优先保真，不用生成图冒充实拍 |
| 缺少素材的场景、氛围、插画、复杂概念视觉 | 确有表达价值时调用 Codex 内置图片工具 | 先检查已有素材；只生成需要的图，并使风格契合主题 |
| 简单图标、装饰、分隔线 | 已有图标库、SVG 或原生形状 | 样式统一，避免无意义装饰 |
| 一句话结论、引言、单个关键指标 | 排版、字号、留白 | 不强制增加图片或关系图 |

用户明确指定某种表现形式时遵循其要求。一般性的“生成配图”结合内容与页面效果自主选择；合适的图片可直接进入生成流程，不要求先尝试 SVG，也不因页面涉及关系或流程而排除配图。

### 关系图的交付

- HTML 可用 SVG、HTML/CSS 或将 Mermaid 渲染为 SVG。保存可修改的 SVG/Mermaid 源码，不用网页截图替代矢量图。
- PPTX 根据表达效果和编辑需要选择原生形状、SVG 或图片，也可组合使用。需要节点级编辑时使用原生形状、文本和连接线；SVG 或位图可作为独立对象嵌入，但不能宣称其内部节点均可单独编辑。
- SVG 是否可嵌入、渲染是否正确，以当前演示工具的实际支持和导出结果为准。兼容性不足时可使用清晰位图兜底，同时保留源文件并说明可编辑性限制。
- 双格式应表达相同关系，不要求使用完全相同的图形实现。检查箭头方向、连线交叉、标签位置和文字可读性。
- 瑞士风保留登记版式；其 SVG 文字标签按原有规则用 HTML 标签承载。图标规范不构成禁止用 SVG 绘制关系图的理由。

## 配图风格服务于主题

在生成前写清：页面主题与受众、图片作用、主体、媒介风格、构图与比例、品牌协调要求。技术方案宜清晰准确，产品介绍宜突出产品，战略或人文内容宜克制自然；不要给所有主题套新能源汽车、蓝色发光线条、芯片、机器人或未来城市。

同组图片保持媒介、光线、饱和度和构图尺度协调；不同内容允许使用不同类型素材，但不混入突兀的视觉语言。品牌色用于页面和必要强调，不要求实景或产品全部染成品牌蓝。不要重画公司 Logo 或二维码。图片不承担需要精确编辑的正文和数据标签。

## 高端、优雅、清晰的布局

- 每页一个主要信息焦点；标题说明结论，正文或图形支撑它，避免多个大标题、装饰和图片同时争夺注意力。
- 先安排内容网格、对齐轴、标题区、主体区和页脚安全区，再放元素。同级信息统一字号、间距、边距与图形尺度。
- 用相关图片、图形和留白共同组织页面，丰富性来自内容与形式的配合。图片应有明确位置和作用，避免无关装饰或挤满空隙；色彩、线条与强调数量保持克制。
- 根据内容形状选择对比、流程、图文或数据布局；整份演示保持一致的字体和视觉规则，同时有适度的版式变化。
- 信息过多时优先精简、分组或拆页，不靠持续缩字、挤压间距、堆叠装饰解决。技术关系准确性和阅读清晰度优先于装饰。
- 检查实际渲染：无重叠与裁切、无拥挤标题、无杂乱连线、主次明确、图文比例协调。不得仅凭代码存在就宣称布局通过。

## 简单位置调整：同一问题最多 3 次

适用于同一元素或同一组元素的对齐、偏移、宽高、边距、间距等简单布局修正。从首次修正开始计数，一次“修改 + 渲染/查看效果”算一次尝试，最多 3 次（不是初次之后再重试 3 次）。

1. 修正前先观察实际页面，明确目标位置和可能原因；优先按元素边界、网格和安全区计算，不反复盲猜坐标。
2. 每次只做有依据的调整并检查结果；成功后结束，不因无实质收益的微调继续循环。
3. 第 3 次仍未到位时，立即停止该问题的调整，保留或恢复到当前最可读的版本，记录问题并继续其他页面。恢复已有版本不触发新一轮尝试。
4. 计数按问题累计，不能因为改了 CSS 属性、换了工具、修改文件名、进入最终检查或换输出格式就重置。同一位置问题涉及 HTML/PPTX 时在一条记录中注明两者表现。
5. 最终检查可以查看已跳过的问题，但不自动再修一轮；只有用户后续明确要求处理时，才重新开启该项修正。

在项目记录中维护未解决项，无问题时不用创建空报告：

| 页码 / 输出格式 | 元素与问题 | 已尝试的修正及次数 | 当前影响 | 建议后续处理 |
|---|---|---|---|---|
| 实际页码与格式 | 期望位置与当前偏差 | 简述每次改动，最多 3 次 | 是否影响阅读或信息完整性 | 手动微调或后续结构调整建议 |

交付时统一列出尚未解决的项，不在每次调整时打断用户。若问题遮挡关键文字或影响阅读，明确标记该页未通过视觉检查；可以继续交付其余成果，但不能将带有未解决问题的演示说成全部通过。该上限不替代内容准确性检查，也不授权隐瞒错误或删掉必需信息。

## 协同制作衔接

实际制作时结合 `integrated-production.md`：在原逐页主稿规划图片作用与图形/文字分层，维护 `images/assets.json` 并核对实际文件，检查页面及全稿节奏。沿用本文件的主题表达和三次位置调整上限，不增加重复确认。
